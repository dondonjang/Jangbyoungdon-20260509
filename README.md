# 생필품 장바구니 비서

35-50세 여성 소비자의 반복 구매 생필품/식료품 재구매 의사결정 비용을 줄이기 위한 AI 쇼핑 비서 MVP입니다.

사용자가 상품 상세 링크를 입력하면 상품을 구조화하고, `자주 사는 상품` 기준으로 동일 상품 가격 비교와 유사 추천 상품 후보를 확인할 수 있도록 설계했습니다.

## 실행 방법

```bash
bun install
bun run dev
```

## 주요 명령어

```bash
bun run build
bun run lint
```

## 핵심 플로우

1. 사용자가 채팅창에 상품 상세 링크를 입력합니다.
2. 서버가 상품 상세 정보를 수집합니다.
3. AI가 상품명, 핵심 속성, 동일 상품/유사 상품 검색 키워드를 구조화합니다.
4. 상품을 `자주 사는 상품`에 저장합니다.
5. 저장 상품 화면에서 동일 상품 후보와 유사 추천 상품 후보를 분리해 보여줍니다.

## 구현 설명 및 설계 의도

### 문제 범위 설정

처음에는 AI 쇼핑 비서가 해결할 수 있는 문제가 넓었습니다.
상품 탐색, 가격 비교, 리뷰 요약, 장바구니 최적화, 재구매 알림까지 모두 가능해 보였습니다.

하지만 범위가 넓으면 MVP에서 무엇을 검증하는지 흐려진다고 판단했습니다.
그래서 35-50세 여성 소비자에게 반복적으로 발생하는 장보기 상황에 집중했습니다.
그중에서도 "새 상품 발견"이 아니라 "이미 자주 사는 상품을 다시 살 때의 비교 피로"로 문제를 좁혔습니다.

### 제품 컨셉

단순 최저가 검색은 기존 가격비교 서비스와 차별점이 약합니다.
더 중요한 페인포인트는 가격을 모르는 것이 아니라, 시간이 부족한데도 판단해야 할 기준이 많다는 점이라고 봤습니다.

그래서 제품 컨셉을 `최저가 검색`이 아니라 `자주 사는 상품 기준의 재구매 의사결정 보조`로 정의했습니다.
UI도 일반 검색 결과가 아니라 `자주 사는 상품`을 중심으로 구성했습니다.
동일 상품과 유사 추천 상품을 구분해 보여주는 이유도 이 때문입니다.

### AI 사용 범위

AI를 전면에 내세우기보다, 사용자가 실제로 체감하는 구매 판단 비용을 줄이는 데 사용했습니다.

AI의 역할은 상품명 정제, 속성 추출, 동일 상품/유사 상품 검색 키워드 생성으로 제한했습니다.
사용자가 보는 가치는 "AI가 생각했다"가 아니라 "내가 다시 살 상품과 대체재가 정리되어 있다"는 경험이라고 판단했습니다.

### 구현 범위 선택

처음부터 여러 커머스를 모두 지원하면 수집 안정성, 데이터 정합성, 추천 품질을 동시에 해결해야 합니다.
그래서 초기 MVP는 제한된 상품 링크 입력과 저장 상품 화면에 집중했습니다.

입력 베이스는 상품 PDP 내 정보고시가 비교적 명확하고 수집 난도가 낮은 컬리로 잡았습니다.
가격 비교 후보는 구조적으로 수집 가능한 다나와를 활용했습니다.
제한된 범위 안에서 문제를 끝까지 검증하기 위한 선택입니다.

## 강조하고 싶은 부분

- 문제를 "AI 쇼핑" 전체가 아니라 반복 구매 의사결정 비용으로 좁혔습니다.
- `자주 사는 상품`을 중심에 두어 사용자의 기존 구매 맥락을 저장하는 구조로 설계했습니다.
- 동일 상품과 유사 추천 상품을 분리해, 최저가와 대체재 판단을 섞지 않으려 했습니다.
- 서버 전용 수집/AI 로직과 클라이언트 UI 경계를 분리했습니다.
- Vercel 배포를 고려해 Cloudflare/Wrangler 구조를 다시 도입하지 않았습니다.

## 아쉬웠던 점과 개선 여지

- 현재 MVP는 지원 입력 범위가 좁습니다.
  컬리 상품 상세 링크 중심으로 검증하고, 이후 다른 커머스와 상품명 입력으로 확장하는 방향이 필요합니다.

- 추천 품질을 더 정교하게 검증해야 합니다.
  AI 키워드만으로는 동일 상품과 유사 상품의 경계가 흔들릴 수 있어, 용량, 브랜드, 모델명, 단위 가격 같은 deterministic signal을 함께 써야 합니다.

- 가격 비교는 실시간성보다 신뢰성이 중요합니다.
  이후에는 수집 시점, 배송비, 쿠폰, 품절 여부를 더 명확히 보여줘야 합니다.

- 실제 사용자 테스트가 필요합니다.
  35-50세 여성 10-20명에게 최근 반복 구매 상품을 입력하게 하고, 저장률, 비교 후보 클릭률, 재사용 의향을 확인하는 실험이 다음 단계입니다.

- 로그인/가족 공유는 후순위로 두었습니다.
  핵심 문제 검증 전에는 범위가 커지기 때문에, 먼저 저장 상품 기반의 재구매 행동이 실제로 발생하는지 확인하는 것이 우선이라고 판단했습니다.
